## خطة العمل واختبارات القبول

1. توسيع السجل الحالي، واستبعاد كل صلاحية حساسة من القوالب، بما فيها إدارة الصلاحيات نفسها. تأسيس مسؤول الوصول يتطلب اختيارًا صريحًا موثقًا منفصلًا عن الأدوار الافتراضية.
2. فحص الصلاحية من قاعدة البيانات داخل المعاملة المالية، باستخدام قفل سياسة الأدوار نفسه؛ لا تكفي صلاحية سابقة من صفحة مفتوحة.
3. فصل طالب العملية عن معتمدها للتسويات والمرتجعات وتعديل السياسة الضريبية وإعادة فتح الفترة. يمنع الاعتماد الذاتي عند وجود موظف آخر فعال يملك العرض والاعتماد. استثناء المسؤول الوحيد يسجل صراحة في التدقيق.
4. طلب المرتجع يتضمن معرف الفاتورة وبنودها وكمياتها فقط؛ يستخرج الخادم القيمة والضريبة وحصة المورد من النسخة الأصلية الثابتة. الاعتماد يُصدر إشعارًا دائنًا ولا يرسل طلب رد مال إلى بوابة دفع.
5. المرتجع بعد السداد ينتج رصيدًا مستحقًا على المورد، ويبقي الفاتورة والتسوية القديمة ثابتتين. تمنع تسوية إيجابية جديدة تتجاوز هذا الالتزام. رد المال لا يحتسب حتى يصل دليل موثوق من مسار مزود الدفع.
6. السياسات الضريبية المعتمدة إصدارات مستقبلية لا تعيد كتابة فواتير سابقة. إعادة فتح الفترة تتطلب صلاحية مستقلة وسببًا وإصدار الفترة المتوقع حتى لا يعتمد طلب قديم على حالة جديدة.
7. إلغاء المستندات المسودة عملية محفوظة ومراقبة بصلاحية مستقلة؛ لا تحذف فاتورة صادرة أو تسوية معتمدة. كل تغيير حساس يحفظ الفاعل والوقت والسجل والقديم والجديد والسبب وبيانات الطلب المتاحة.
8. المطابقة تحفظ نسخة المصادر المالية التي تمت مراجعتها وبصمتها. وجود اختلاف جوهري يمنع تسجيل نجاح المطابقة؛ لا يغير زر المراجعة المبالغ أو يمحو الاختلافات.
9. دورة بيع معزولة تستخدم خدمات الطلب والتحصيل والفاتورة والاستحقاق والشحن التجريبي والتسوية والإقفال والمرتجعات. مصدر الأموال وأحداث الشحن بيانات اختبار داخل قاعدة MySQL مؤقتة فقط.
10. اختبارات منع تجاوز الصلاحيات، التزامن، تكرار الطلب، فشل التدقيق، الفترات المقفلة، ثم جميع Unit/Integration وTypeScript وESLint والبناء.

## الصفحات والقدرات الجديدة

| الصفحة | الصلاحيات المستقلة |
|---|---|
| `/admin/access-control` | `access_control:view` و`access_control:manage_settings` |
| `/admin/finance?section=settlements` | إنشاء، اعتماد، عكس مالي، وإلغاء مسودة، كل منها مستقل |
| `/admin/finance?section=returns` | `returns:view/create/approve/refund/export/delete` |
| `/admin/finance?section=tax` | `tax:view/manage_settings/approve/export` |
| `/admin/finance?section=close` | `periods:view/close_period/reopen_period/approve` |
| `/admin/finance?section=reconciliation` | `reconciliation:view/reconcile/export` |
| `/admin/finance?section=invoices` | عرض وإنشاء وتصدير وإلغاء المسودة دون مسح المستند الصادر |
| `/admin/finance?section=ledger` | قراءة سجل التدقيق وتصديره بحسب المنح |

القراءة أو إنشاء الطلب لا يمنح الاعتماد. صلاحيات التصدير المالي، رد المال، اعتماد المرتجعات، التسويات، تعديل الضريبة واعتمادها، الإقفال وإعادة الفتح، إلغاء المسودات، وإدارة الوصول لا تمنح افتراضيًا.

## حدود التحقق

هذه المرحلة لا تفعل الشراء أو الدفع أو سلة أو CJ، ولا تنشئ تفويض متجر حقيقي. اختبار المزود الحقيقي وMerchant ID وصلاحيات العملاء والطلبات يظل مرتبطًا بتفويض صاحب المتجر ومرحلة اختبار منفصلة. إصدار فاتورة ضريبية للاستخدام الحقيقي يظل خلف سياسة مالية معتمدة؛ نجاح البيانات المصطنعة ليس اعتمادًا نظاميًا للفوترة.
