# خارطة طريق المنتج — تربّح ×10

> مراجعة للقاعدة الكودية الحالية لاستخراج الميزات التي تضاعف القيمة عشر مرات،
> مرتّبة في ثلاث موجات، ولكل ميزة **معايير قبول قابلة للفحص** (تتحول لاحقاً إلى اختبارات).

---

## القراءة الاستراتيجية: أين تتسرّب القيمة اليوم؟

من فحص الكود، حلقة القيمة الحالية:

```
بائع ينشر ← مشترٍ يتصفح ← زر واتساب/اتصال ← الصفقة تتم خارج المنصة ❌
```

**كل ما بعد الضغط على «واتساب» غير مرئي للمنصة**: لا نعرف أي إعلان باع، ولا قيمة الصفقات،
ولا نستطيع أخذ عمولة أو حماية مشترٍ. إيراد المنصة اليوم = باقات تمييز + بانرات فقط.

**معادلة الـ×10**: سحب لحظة الصفقة إلى داخل المنصة (موجة 2)، مع رفع الثقة والاحتفاظ
والانتشار أولاً (موجة 1) لأنها شروط نجاح الموجة 2.

### أصول موجودة في الكود تُبنى عليها مباشرة
| الأصل | الملف | يخدم |
|---|---|---|
| PWA + Service Worker + manifest | `public/sw.js` | إشعارات Push، تطبيق Play (TWA) |
| تطبيع عربي مُختبَر | `src/domain/text.ts` | البحث الذكي |
| متاجر معتمدة بهوية وتقييمات | `src/lib/merchant.ts` | RFQ، الطلبات، الكوبونات |
| محادثات داخلية بمؤشر كتابة | `src/lib/chat.ts` | مفاوضات RFQ |
| نوع إعلان «طلب» | `ads.adsType='request'` | نواة RFQ |
| مواقع وخرائط ومسافات | `src/lib/geo.ts`, `maps.ts` | الشحن والتوصيل لاحقاً |
| إشراف نصي+صوري تلقائي | `content-guard`, `nsfw` | يغطي كل محتوى جديد |
| Redis + `cached()` | `src/lib/redis.ts` | أداء أي ميزة جديدة |
| توثيق يدوي بشارة | `trusted` + `verifications` | الترقية لتوثيق سجل تلقائي |

## الموجة 1 — الثقة والاحتفاظ والانتشار (أسابيع، أثر فوري)

### 1.1 إشعارات فورية Push 🔔
**لماذا**: أكبر رافعة احتفاظ متاحة؛ البنية (PWA/SW) جاهزة بنسبة 80٪.
**البناء**: Web Push (VAPID) + جدول `push_subscriptions` + نقاط إطلاق في: رسالة جديدة،
اعتماد إعلان/متجر، تقييم جديد، بلاغ يحتاج رد، عرض سعر وارد (موجة 2).

**معايير القبول:**
- [ ] زر تفعيل الإشعارات يظهر للعضو المسجّل (غير مزعج — بعد أول تفاعل، وليس عند أول زيارة).
- [ ] وصول إشعار رسالة جديدة **والتطبيق مغلق**، والنقر يفتح المحادثة نفسها (deep link).
- [ ] لوحة تفضيلات: تشغيل/إيقاف لكل نوع إشعار على حدة.
- [ ] إلغاء الاشتراك يُنظّف الاشتراكات الميتة (410 Gone) تلقائياً.
- [ ] لا يُرسل أي إشعار لمحتوى حذفه الإشراف.

### 1.2 البحث العربي الذكي 🔍
**لماذا**: البحث الحالي `LIKE` حرفي — «موبايل» لا يجد «جوال»، و«أحمد» لا يجد «احمد».
**البناء**: عمود `title_norm` مفهرس يُملأ بـ`normalizeAr` (الموجودة والمُختبَرة)، FULLTEXT
على العنوان/التفاصيل، قاموس مرادفات تجاري قابل للتحرير من الإدارة، وفلاتر مدمجة (سعر/مدينة/قسم/عرض-طلب).

**معايير القبول:**
- [ ] البحث بـ«احمد» يجد إعلانات «أحمد» والعكس (كل أشكال الألف/التاء المربوطة/المقصورة).
- [ ] مرادفات: «جوال» يجد «موبايل» و«هاتف» (قائمة تديرها الإدارة من لوحة التحكم).
- [ ] فلاتر السعر والمدينة والقسم تعمل مجتمعة مع نص البحث.
- [ ] زمن الاستجابة < 200ms على 100 ألف إعلان (يُقاس ويوثَّق).
- [ ] صفر نتائج → اقتراح «هل تقصد…» + أقرب نتائج مخفَّفة الشروط.

### 1.3 توثيق السجل التجاري تلقائياً (واثق) 🏛️
**لماذا**: الثقة هي عملة B2B. حقل السجل موجود (`stores.national_id`) لكنه غير مُتحقَّق.
**البناء**: تكامل مع API «واثق» السعودي: التاجر يُدخل رقم السجل → تحقق آلي من مطابقة
الاسم → شارة **«سجل تجاري موثّق»** مع لقطة بيانات محفوظة للإدارة.

**معايير القبول:**
- [ ] إدخال سجل صحيح مطابق ⇒ الشارة تظهر خلال دقيقة بلا تدخل إداري.
- [ ] سجل منتهٍ/غير مطابق ⇒ رفض بسبب واضح + تحويل لمسار التوثيق اليدوي القائم.
- [ ] لقطة بيانات واثق (الاسم، الحالة، النشاط، تاريخ الانتهاء) محفوظة وتظهر للإدارة فقط.
- [ ] الشارة تنعكس في: واجهة المتجر، بطاقات الإعلانات، نتائج البحث.
- [ ] إعادة التحقق التلقائي كل 90 يوماً؛ انتهاء السجل يسحب الشارة وينذر التاجر.
- ⚠️ **يلزم منك**: اشتراك واثق (مفتاح API).

### 1.4 تطبيق Google Play عبر TWA 📱
**لماذا**: قناة توزيع كاملة بتكلفة شبه صفرية — الـPWA جاهز والأيقونات عند المصمم.
**البناء**: تغليف Trusted Web Activity (Bubblewrap) + `assetlinks.json` + إشعارات Push
تعمل داخل التطبيق.

**معايير القبول:**
- [ ] التطبيق يجتاز مراجعة Google Play وينشر.
- [ ] الجلسة مشتركة: دخول في المتصفح = دخول في التطبيق (نفس النطاق).
- [ ] إشعارات 1.1 تصل داخل التطبيق.
- [ ] لا شريط عنوان متصفح (تحقق النطاق سليم).
- ⚠️ **يلزم منك**: حساب مطوّر Play (25$ لمرة واحدة) + أيقونات المصمم (1024 + Feature Graphic).

## الموجة 2 — المعاملات داخل المنصة (قلب الـ×10) 💰

### 2.1 نظام عروض الأسعار RFQ (مناقصات مصغّرة)
**لماذا**: هذا ما يميّز B2B عن المبوّبات العادية (نموذج Alibaba). إعلان «طلب» اليوم سلبي —
يصبح مناقصة حيّة يتنافس عليها التجار.
**البناء**: جدول `quotes` مربوط بإعلانات الطلب: تاجر معتمد يقدّم (سعر، كمية، مدة توريد،
ملاحظة)؛ صاحب الطلب يقارن في جدول ويُرسي؛ التفاوض يكمل في المحادثات الموجودة.

**معايير القبول:**
- [ ] إعلان طلب يحمل: كمية، مواصفات، موعداً نهائياً للعروض، مدينة تسليم.
- [ ] **فقط أصحاب المتاجر المعتمدة** يقدّمون عروضاً (يبني على بوابة الاعتماد القائمة).
- [ ] العروض **سرّية**: كل تاجر يرى عرضه فقط؛ صاحب الطلب يراها كلها في جدول مقارنة.
- [ ] إشعار Push لصاحب الطلب عند كل عرض، وللتاجر عند الإرساء/الرفض.
- [ ] انتهاء الموعد يقفل التقديم تلقائياً ويُعلم الجميع.
- [ ] الإرساء يفتح محادثة مباشرة ويَسِم الطلب «مُرسى» (يختفي من التصفح العام).
- [ ] تاجر لا يستطيع تقديم عرضين على نفس الطلب (تعديل عرضه القائم فقط).

### 2.2 الطلبات والدفع الإلكتروني (mada / Apple Pay)
**لماذا**: تحويل «زر واتساب» إلى «اشترِ الآن» = رؤية كاملة للصفقات + **عمولة = خط إيراد جديد**
+ تفعيل «مبيعات المتجر» الحقيقية التي طلبتها سابقاً وكانت محجوبة بغياب نظام طلبات.
**البناء**: جدول `orders` بدورة حياة (جديد → مؤكد → مشحون → مستلم → مكتمل/نزاع)،
بوابة دفع سعودية (Moyasar أو Tap — قرارك التجاري)، عمولة قابلة للضبط من الإدارة،
ولوحة «مبيعاتي» داخل المتجر تكتمل بها الإحصائيات الموجودة.

**معايير القبول:**
- [ ] «اشترِ الآن» على إعلانات المتاجر المعتمدة ذات السعر المحدد (لا يظهر لـ«على السوم»).
- [ ] دفع ناجح بـ mada وApple Pay في بيئة الاختبار ثم الإنتاج.
- [ ] فشل الدفع لا يُنشئ طلباً؛ نجاحه يُنشئه «مؤكداً» ويُشعر الطرفين (Push + SMS).
- [ ] عمولة المنصة (٪ قابلة للضبط) تُحتسب وتظهر في تقرير إيراد إداري.
- [ ] البائع يحدّث الحالة حتى «مشحون»؛ المشتري يؤكد الاستلام؛ 3 أيام بلا تأكيد بعد الشحن = إكمال تلقائي مع إشعار.
- [ ] «مبيعات المتجر» في لوحة التاجر: عدد، إجمالي، متوسط قيمة الطلب، أفضل المنتجات.
- [ ] كل طلب مرتبط بمحادثة؛ زر «نزاع» يجمّد الإكمال ويفتح تذكرة للإدارة (تُعرض في قسم إدارة المتاجر).
- ⚠️ **يلزم منك**: حساب لدى بوابة الدفع (سجل تجاري + حساب بنكي) وتحديد نسبة العمولة.

### 2.3 كوبونات وعروض المتاجر 🏷️
**لماذا**: أدوات تسويق للتاجر تزيد التزامه بالمنصة، وقابلة للتسييل (ميزة ضمن الباقات الذهبية).
**البناء**: جدول `store_coupons` (نسبة/مبلغ، انتهاء، سقف استخدام) يظهر على واجهة المتجر
وبطاقات إعلاناته، ويُطبَّق في الطلبات (2.2).

**معايير القبول:**
- [ ] التاجر ينشئ كوبوناً بنسبة أو مبلغ، بتاريخ انتهاء وسقف استخدامات.
- [ ] شريط «خصم X٪ بكود Y» يظهر على واجهة المتجر وبطاقات منتجاته (كل أنماط الكتالوج الأربعة).
- [ ] الكود يُطبَّق في الطلب ويخفض المجموع فعلياً، ويُرفض بعد الانتهاء/السقف برسالة واضحة.
- [ ] إنشاء الكوبونات حصري لباقة معيّنة (قابل للضبط من إدارة الباقات القائمة).

## الموجة 3 — التوسّع والنظام البيئي 🚀

### 3.1 قُمع تحليلات التاجر (مشاهدة → تواصل → صفقة)
**البناء**: تسجيل نقرات واتساب/اتصال/مراسلة (اليوم غير مقيسة!) + دمج بيانات الطلبات.
**معايير القبول:**
- [ ] كل نقرة تواصل تُسجَّل (بلا معلومات شخصية عن الزائر).
- [ ] لوحة التاجر تعرض القمع كاملاً لكل إعلان: مشاهدات → تواصلات → طلبات.
- [ ] ملخص أسبوعي يصل Push مع أفضل إعلان وتوصية واحدة قابلة للتنفيذ.

### 3.2 مساعد النشر الذكي ✨
**البناء**: من صورة + كلمات قليلة → عنوان ووصف عربي احترافي وتصنيف مقترح وسعر استرشادي
من الإعلانات المشابهة (similarity الموجودة).
**معايير القبول:**
- [ ] مسودة كاملة خلال < 5 ثوانٍ من رفع صورة وكتابة ≥ 3 كلمات.
- [ ] السعر الاسترشادي يستشهد بـ3 إعلانات مشابهة حقيقية.
- [ ] الناتج يمر على حارس المحتوى نفسه قبل العرض؛ وقياس نسبة قبول المسودات دون تعديل.

### 3.3 استيراد الكتالوج وAPI للمتاجر 🔗
**البناء**: استيراد CSV (وقالب متوافق مع تصدير سلة/زد) + API بمفتاح لكل متجر معتمد.
**معايير القبول:**
- [ ] استيراد 500 منتج CSV في أقل من دقيقة مع تقرير أخطاء لكل صف مرفوض.
- [ ] كل منتج مستورد يمر على الإشراف النصي/الصوري القائم — لا التفاف على الحماية.
- [ ] مفتاح API يُصدر ويُبطل من لوحة التاجر؛ حد 60 طلباً/دقيقة؛ صفحة توثيق عربية.

### 3.4 الشحن والتوصيل (بعد 2.2)
تكامل مزوّد شحن سعودي (تورود/أرامكس) بأسعار حيّة وتتبع داخل الطلب — يمدّ خرائط `geo.ts`
الموجودة. معاييره تُفصَّل عند بدئه.

## قرارات/مدخلات مطلوبة منك قبل كل موجة
- **الآن (موجة 1)**: مفتاح واثق · حساب Google Play · أيقونات المصمم · بيانات 4jawaly (لإشعارات SMS في 2.2).
- **قبل موجة 2**: اختيار بوابة الدفع (Moyasar/Tap) وفتح الحساب · نسبة العمولة.
- **قبل 3.2**: ميزانية مزوّد الذكاء الاصطناعي (تكلفة لكل إعلان مولَّد).
