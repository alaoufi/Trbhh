# الموردون وربط API — تشغيل آمن

## ما الذي يبيعه الموقع؟

العميل يشتري السلعة المعتمدة من تربح. المورد جهة داخلية لتنفيذ التوريد والتسوية خارج الموقع، ولا تُعرض للعميل بيانات المورد الخاصة أو تكلفة التوريد. الإعلان العادي يظل للتواصل خارج الموقع.

## إعداد المورد

من إدارة الموردين: الاسم، مسؤول التواصل، الجوال، البريد، العنوان، السجل التجاري، الرقم الضريبي، شروط التسوية والملاحظات الداخلية. المورد الجديد موقوف افتراضيًا. تنشيط المورد يسمح بربط سلعه وإجراء طلبات جديدة عليه يدويًا؛ لا ينشط API ولا يصرف له أي مبالغ.

لكل سلعة معتمدة يمكن اختيار مورد ورمز سلعة لديه وتكلفة الوحدة بالريال. عند إنشاء الطلب تحفظ هوية المورد واسمه ورمز السلعة والتكلفة والكمية كنسخة تاريخية. تعديل المورد أو التكلفة لاحقًا لا يعيد حساب طلب قديم. السلع غير المرتبطة بمورد تُعامل كمخزون داخلي/غير مسند، ولا تُنسب إلى مورد افتراضي.

إيقاف المورد يمنع الطلبات الجديدة المرتبطة به، لكنه لا يُسقط حقوق طلب قديم أو يمنع تسوية دفع بنكي سبق بدء محاولته.

## حقل API والأسرار

- رابط API اختياري بصيغة HTTPS، بلا كلمة مرور أو مفتاح داخل الرابط، وبلا query أو fragment.
- حقل مرجع المفتاح يقبل اسم متغير مخصص مثل `TRBHH_SUPPLIER_VENDOR_TOKEN`، وليس قيمة المفتاح نفسها.
- يضع مسؤول الخادم القيمة الفعلية في مخزن الأسرار/بيئة الخادم خارج المستودع. لا ترسلها في المحادثة أو صور الشاشة.
- حفظ الرابط أو مرجع المفتاح لا يجري اتصالًا ولا يرسل بيانات العملاء.
- في هذا الإصدار لا يوجد موصل مورد مسجل: تشغيل API محجوب خادميًا وواجهته موقوفة. ليست هذه مزامنة كتالوج أو إرسال أوامر شراء عاملة.

عند توفر وثائق المورد: يبنى موصل خاص يراجع المصادقة والصلاحيات وصيغ الطلب/الاستجابة، ويثبت عنوان الوجهة ونطاقاتها المسموحة ويتحقق من DNS وعناوين الشبكات عند الاتصال ويمنع التحويلات. التحقق الشكلي من الرابط وحده ليس حماية كافية من SSRF. تُختبر إعادة المحاولات ومنع تكرار أوامر المورد في بيئته التجريبية أولًا. لا يتغير قرار «لا دفع آلي للمورد».

## تأكيد البنك وسجل الحسابات

قبل إثبات الدفع لا يوجد إيصال تحصيل ولا استحقاق مورد ناتج عن الدفع. بعد التحقق الخادمي من البنك ومطابقة المرجع والعملة والمبلغ والطلب، تُحفظ حالة الدفع والإيصال واستحقاقات الموردين والتنبيهات في معاملة واحدة. فشل حفظ السجل يُرجع المعاملة؛ تكرار تأكيد البنك لا ينشئ قيدًا مكررًا.

هذا سجل تشغيلي للتحصيل وتوزيع مستحقات الموردين، وليس دفتر أستاذ محاسبيًا أو نظام فواتير ضريبية معتمدًا. حالة `offline_pending` تعني انتظار متابعة التسوية خارج الموقع، لا أن المورد قبض مستحقاته. لا يوجد زر يدوي لتزوير تأكيد البنك.

## قبل أي تفعيل حي

ربط البنك الحالي للشراء المباشر ما زال مغلقًا. يلزم موصل موثق واختبار بنكي مفوض، ومراجعة التشغيل والإلغاء والاسترداد، ونسخة احتياطية حديثة وإثبات رجوع. لا تُنقل قواعد الاختبار المحلية ولا حساباتها إلى الإنتاج. لا يكفي وضع مفتاح API لتجاوز الاختبارات أو تشغيل الربط.
