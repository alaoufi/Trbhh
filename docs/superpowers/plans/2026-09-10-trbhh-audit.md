# خطة تنفيذ إصلاحات المراجعة

> التنفيذ في النسخة المعزولة وعلى الفرع الموافق عليه فقط. المهام المستقلة موزعة مع ملكية واضحة للملفات، يليها تكامل ومراجعة.

- [x] البيانات: `account.ts`, `analytics.ts`, `merchant.ts`, `store-subscription-access.ts`، وصفحات إعلاناتي/المفضلة وبطاقة الإحصاءات. اختبارات الفترة والاشتراك والإسقاط.
- [x] الدخول: سياسة موحدة لكلمات المرور، TOTP وتسجيله واسترداده ومقاومة إعادة الاستخدام، واجهات الدخول والحماية. اختبار الفشل والنجاح والتجاوزات.
- [x] الواجهة العامة: الرئيسية، البحث، بطاقة الإعلان، التواصل، نوافذ الترحيب والتثبيت والتوثيق. فحص فلاتر البحث وبيانات البطاقات وتنسيق النوافذ.
- [x] المتجر: صفحة عرض قبل الدخول، خطوات إنشاء مع الحفاظ على البيانات والتحقق قبل الإرسال، وتصحيح رابط المعاينة.
- [x] الإدارة والتوثيق: مفاتيح الميزات ونصوصها وأدلة الصفحات الثلاثة وملاحظات تفعيل الحماية لاحقاً.
- [x] تحقق متكامل: تثبيت بالـ lockfile، TypeScript، ESLint، Vitest، بناء Next.js، وأربعة اختبارات معاملات على MySQL معزولة؛ فحص مكوّن إعداد المتجر الفعلي محلياً على سطح المكتب وعرض 390px. التفاصيل وحدود التحقق في تقرير التسليم.
- [x] مراجعة مستقلة للمتطلبات ثم الجودة والأمان، إصلاح النتائج، حفظ commit عربي ورفع الفرع صراحةً دون دمج أو نشر.

## الحماية من النشر

فرع الإنتاج الافتراضي الفعلي `claude/hostinger-vps-project-amw8vb` وليس main. رفعه يطلق النشر. فرع staging يطلق نشر التجريب. فرع العمل لا يطابق أياً منهما. أزيل upstream الإنتاج من الفرع الجديد. يستخدم الرفع refspec صريحاً لفرع المراجعة فقط.
