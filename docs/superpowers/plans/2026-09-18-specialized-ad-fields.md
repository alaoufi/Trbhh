# نظام الحقول المتخصصة حسب القسم الفرعي Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended) or superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** تنفيذ قوالب حقول عميقة وآمنة وقابلة للإدارة لكل قسم فرعي، مع عرض الحقول المعبأة فقط وأداء قابل للقياس.

**Architecture:** ستُضاف علاقة اختيارية بالقسم الفرعي إلى تعريفات الحقول، مع أنواع وقواعد تحقق وشروط ظهور محفوظة بشكل آمن. تُجلب القوالب حسب القسم المختار فقط، وتُحفظ القيم مع فهارس مناسبة، وتُعرض القيم غير الفارغة فقط. لوحة الإدارة تدير دورة حياة الحقل بالأرشفة لا بالحذف المدمر.

**Tech Stack:** Next.js App Router, TypeScript, Prisma/MySQL, Redis, Vitest, GitHub Actions.

---

### Task 1: تثبيت نموذج البيانات والتحقق

**Files:** `prisma/schema.prisma`, `src/data/schema-sync.ts`, `src/domain/category-fields.ts`, tests for category validation.

- [ ] إضافة `subcategory_id`, `visibility_rule`, `unit`, `searchable`, `archived_at` لتعريف الحقل مع فهارس مركبة.
- [ ] جعل قراءة القالب تعتمد على القسم الفرعي مع وراثة الحقول المشتركة فقط.
- [ ] إضافة تحقق للرقم والوحدة والمدى والقوائم والقيم الشرطية.
- [ ] كتابة اختبارات فاشلة أولاً ثم تنفيذها: رفض حقل غريب، قبول قالب صحيح، إلزام مشروط، وعدم قبول قيم خارج الخيارات.

### Task 2: قوالب جميع الأقسام

**Files:** `src/domain/category-catalog.json`, `scripts/preview/seed.mjs`, seed/schema helpers.

- [ ] إنشاء قوالب تفصيلية للأقسام الثمانية التجارية والعقارات والسيارات والنقليات والزراعة والمواشي والأواني والديكور ومواد البناء، إضافة إلى الوظائف والخدمات والفرص والمنتجات وأخرى.
- [ ] تخصيص الفروع: أرض/فيلا/شقة، سيارة/قطع/خدمة، شاحنة/رافعة، مشتل/أعلاف، مواشي/طيور، وهكذا.
- [ ] عدم جعل «جديد/مستعمل» مشتركاً؛ لا يظهر إلا في قوالب المنتجات والمركبات والمعدات حيث يناسب.
- [ ] منع تفعيل قالب فرعي ناقص في seed والتحقق من اكتماله آلياً.

### Task 3: نموذج الإضافة والتعديل

**Files:** `src/components/ad-form.tsx`, category picker/field components, `src/app/ads/actions.ts`, `src/lib/categories-v2.ts`.

- [ ] عرض القسم الفرعي أولاً ثم الحقول المناسبة له فقط.
- [ ] دعم الشروط: بيع/إيجار، نوع العقار، نوع المنتج، ونوع الخدمة.
- [ ] التحقق server-side من كل قيمة ومن ملكية الحقل للقسم.
- [ ] حفظ مسودة صالحة عند النقص، ومنع النشر فقط عند نقص الحقول الإلزامية النشطة.
- [ ] عدم فقد القيم القديمة عند أرشفة حقل أو تغييره.

### Task 4: العرض والبحث

**Files:** `src/components/ad-category-details.tsx`, ad detail/card/search data loaders and query builders.

- [ ] عرض الحقول النشطة ذات القيم فقط، وإخفاء المجموعة الفارغة.
- [ ] إضافة فلاتر للحقول المعلّمة searchable فقط.
- [ ] استخدام استعلامات محددة وفهارس وعدم تنفيذ N+1.
- [ ] إضافة cache للقوالب العامة مع إبطالها بعد تعديل الإدارة.

### Task 5: لوحة الإدارة ودورة الحياة

**Files:** `src/app/admin/categories`, new field-management components/actions, `src/lib/roles.ts`, settings/guide pages.

- [ ] إضافة إنشاء وتعديل وأرشفة واستعادة الحقل.
- [ ] التحكم في الاسم والنوع والوحدة والخيارات والإلزام والترتيب والشرط والبحث.
- [ ] إظهار عدد الإعلانات المتأثرة وتسجيل كل تغيير.

### Task 6: الأمان والأداء

**Files:** relevant actions, upload validation, rate limiting, indexes.

- [ ] تحديد أطوال النصوص والأرقام والخيارات والطلبات وعدد الصور.

- [ ] إضافة rate limits للنشر والبحث والرفع وتعديل القوالب.
- [ ] قياس زمن القالب والبحث وصفحة الإعلان وقراءة الاستعلامات، وتحسين الاستعلامات والفهارس والصور.
