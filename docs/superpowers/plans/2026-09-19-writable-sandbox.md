# التجريبية القابلة للحفظ — تنفيذ معزول

الموافقة: المستخدم طلب إكمال التجريبية بالبيانات والأقسام والتصميم والخدمات، وعدم النقل للفعلي قبل نجاح التجربة. تصنيف الإعلانات القديمة مؤجل.

## القرار

استمرار طلب صلاحية إدارية من قاعدة الإنتاج ليس شرطًا لإنشاء قاعدة اختبار. نستخدم MySQL مستقلة باسم `trbhh_preview_v2` ومشروع Docker مستقل `trbhh-preview-v2` ومجلد `/root/trbhh-preview-v2`. لا تعدّل بيئة المعاينة الأقدم `trbhh-preview-audit` أو الإنتاج. تُنسخ البيانات العامة فقط من اللقطة المدققة، وتستخدم حسابات اختبار، دون كلمات مرور أو هواتف أو أسرار إنتاج. اللقطة ليست اتصالًا حيًا مستمرًا.

## المهام

- [ ] بوابة `PREVIEW_SANDBOX=true` ترفض قواعد الإنتاج أو معاملات اتصال متجاوزة، وتمنع مسارات الدفع والتكاملات الخارجية. تبقى الشبكة الداخلية بلا خروج.
- [ ] حفظ بيانات نموذج الإعلان ومسوداته في جدول منفصل لكل مستخدم تجريبي، مع مصادقة وحماية أصل الطلب وحد حجم وتعارض إصدارات. النجاح يظهر بعد تأكيد قاعدة البيانات فقط.
- [ ] ربط النموذج ولوحة إعلاناته داخل القالب الأصلي دون تغيير سلوك الموقع العادي أو المعاينة الثابتة.
- [ ] إدخال لقطة عامة مدققة إلى قاعدة فارغة فقط، مع إبقاء النص والصور والمعرّفات، وإظهار مصدر البيانات وتاريخ اللقطة. لا تنتحل حسابات المعلنين الحقيقيين.
- [ ] تجهيز نشر يدوي مقيد بفرع المعاينة ونجاح فحوصاته، بأسرار مستقلة ونسخ احتياطية للمشروع التجريبي وحده.
- [ ] اختبار المصادقة والحفظ وإعادة الفتح وتعارض المستخدمين والجوال والصور وحدود الشبكة قبل تقديم الرابط.

## الحدود

هذه المرحلة لا تفعّل الإنتاج، ولا تغيّر حساب إدارة MySQL، ولا تمنح الإدارة لكل زائر، ولا تدفع أو ترسل رسائل حقيقية. المدفوعات الفعلية غير متاحة؛ اختبار مزود sandbox يحتاج تجهيزًا منفصلًا. أي جزء غير مختبر يُذكر صراحة ولا يُعلن اكتمال جميع الخدمات.
