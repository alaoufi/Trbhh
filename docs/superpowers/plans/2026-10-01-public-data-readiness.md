# خطة إغلاق جودة البيانات العامة قبل المراجعة الخارجية

## القيود

- العمل على `codex/trbhh-platform-enhancement-20260929` فقط.
- لا دمج ولا نشر إلى الإنتاج ولا كتابة في قاعدة البيانات الحية.
- تظل المعاينة المتصلة بالبيانات الحية للقراءة فقط، والشراء الحي معطلاً.
- الاحتفاظ بالقيم التاريخية في قاعدة البيانات لا يعني عرضها للعامة.

## 1. تدقيق التصنيف والأثر العام

1. توسيع نموذج التدقيق ليعطي سببًا دقيقًا لكل `invalid_subcategory` بدل التصنيف العام.
2. فصل أثر المشكلات إلى `BLOCKING_PUBLIC` و`SAFE_LEGACY` و`EDITORIAL_ONLY` و`NEEDS_EDITOR_REVIEW`.
3. إثبات الحالات القطعية القابلة لإعادة الربط، وإخراج خطة تصحيح فقط دون تنفيذها على البيانات الحية.
4. إضافة اختبارات فاشلة أولًا لكل سبب وتصنيف أثر، ثم تنفيذ الحد الأدنى اللازم.

## 2. سلامة الحقول العامة

1. منع عرض القيم القديمة غير المتوافقة مع تعريف الـLeaf الحالي مع إبقائها مخزنة.
2. إضافة فحص دلالي محافظ يمنع إظهار مجموعة المواصفات كلها عندما يتعارض نص الإعلان بوضوح مع عائلة الـLeaf المختارة؛ لا يعيد التصنيف تلقائيًا من العنوان.
3. تضييق حقول الرفع: فصل حمولة الرافعة العامة والشوكية والتلسكوبية ومنصات القص/الأفراد، ورفض الحدود غير المنطقية في الإدخال الجديد.
4. توسيع Schema المقاولات ليشمل الأسوار والشبوك وأعمال النخيل كي لا يضطر المعلن لاختيار Schema أدوات.

## 3. الموقع والعدّ العام

1. استبعاد السجلات ذات علاقة مدينة/منطقة غير موثوقة من `/nearby` ومن تعزيز الترتيب الجغرافي.
2. توحيد عدد إعلانات الرئيسية مع نفس شروط الظهور في البحث.
3. إضافة تفصيل قراءة فقط للفارق السابق بين عداد النشط ونتائج البحث حسب سبب الاستبعاد.

## 4. مصادر Schema والمراجعة المهنية

1. إنشاء سجل مراجعة صريح يغطي كل قوالب الـLeaf بلا fallback مجهول.
2. تسجيل المصدر الفعلي لكل Leaf حي: DB أو code template أو inherited أو fallback.
3. إخراج عدد الحقول والمطلوبة والمشروطة وحالة المراجعة المهنية مع سبب أي حالة غير PASS.
4. اختبار يفشل إذا أضيف Leaf بلا مصدر أو بلا مراجعة.

## 5. QA المتصفح والروابط

1. توسيع رحلة قاعدة الاختبار المعزولة لتغطي عينة من كل عائلة Schema رئيسية عبر الإنشاء والتفاصيل والتعديل والبحث/الفلتر.
2. إضافة crawler عام مجهول لكل روابط GET الداخلية المكتشفة في Preview، مع توزيع HTTP وقائمة 404/500.
3. إبقاء الاتصالات الخارجية والمدفوعات وطلبات الموردين معطلة أثناء الاختبار.

## 6. البوابات والتقرير

1. تشغيل الاختبارات المستهدفة ثم Prisma validate وTypeScript وlint وكامل tests وbuild.
2. نشر Preview فقط من SHA الفرع عبر المسار الحالي للقراءة فقط، ثم تشغيل التدقيق الحي والـcrawler.
3. استبدال قرار التقرير السابق بـ`READY FOR FINAL EXTERNAL REVIEW` فقط عند تحقق الشروط الجديدة، وإلا توثيق الموانع بالأعداد الدقيقة.
4. لا تستخدم عبارة `READY FOR PRODUCTION` في هذه الجولة.
