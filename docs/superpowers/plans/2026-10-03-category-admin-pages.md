# تبسيط إدارة حقول الأقسام

**Goal:** فصل إضافة وتعديل الحقول عن إلزامها وظهورها بعبارات عربية مفهومة، دون تغيير القيم الحالية تلقائيًا.
**Architecture:** ثلاثة مسارات تحت `/admin/categories/subcategories/[id]/[section]`: fields / requirements / display. تستخدم AdCategoryEditor نفسه وsaveSubcategory نفسه وإصدار التعريف للحماية من الكتابة المتزامنة. الأجزاء غير المعروضة تُرسل كما هي، ولا migration ولا تغيير بيانات قديمة.
**Tech Stack:** Next.js / React / TypeScript / Vitest / Playwright.

التصميم المعتمد من طلب المستخدم: صفحة الأقسام تعرض روابط واضحة بدل محرر طويل لكل قسم فرعي. إضافة الحقول في fields؛ صفحة requirements تعرض إجباري / اختياري / إجباري حسب شرط موجود مع شرح للحقل المخفي؛ display تعرض جملًا كاملة لأماكن الاستخدام. تحويل حقل مشروط بالإلزام إلى اختياري يزيل شرط الإلزام فقط، ولا يحوّل الشرط إلى إخفاء أو ظهور. شروط الظهور الأخرى تبقى كما هي.

- [ ] كتابة اختبارات عرض الأوضاع الثلاثة، ثبات JSON الأصلي، وإبقاء شروط الظهور عند تغيير الإلزام؛ تشغيلها وفشلها قبل التنفيذ.
- [ ] إضافة مساعد presentation للتحويل وعناوين الصفحات؛ فصل UI داخل المحرر الحالي دون نسخ منطق الحفظ.
- [ ] إضافة مسار محمي مع 404 للأقسام/الصفحات غير الموجودة، وروابط من إدارة الأقسام؛ redirect محلي مضبوط بعد الحفظ مع revalidation.
- [ ] تحديث أدلة العضو والمتجر والإدارة؛ اختبار UI معزول للحفظ والاسترجاع وعدم تسرب التغييرات بين الصفحات.
- [ ] اختبارات مستهدفة ثم TypeScript/lint/build؛ commit عربي، Preview، Backup، بوابة E2E، نشر الصورة المختبرة وتوثيق SHA.

التحقق: `pnpm exec vitest run tests/unit/category-admin-pages.test.ts tests/unit/ad-category-form-policy.test.ts`؛ فحص UI حقيقي عبر بوابة الاختبار المعزولة، لا تعديل إعدادات أقسام الإنتاج خلال الاختبار.
