# قياس سعة البحث المحلي وتحسينها

التصنيف P1 بسبب موارد الإنتاج. المستخدم فوّض التنفيذ والتحسين، ويشغّل أوامر SSH بنفسه.

1. توحيد الطلبات المتطابقة داخل العملية: طلب نموذج واحد، حتى 64 مستفيدًا، مهلة مستقلة لكل مستفيد، دون طابور للطلبات المختلفة. الاحتفاظ بحد الذاكرة 1MiB و128 نتيجة وساعة صلاحية. لا تغيير للنموذج أو جودة التعليمات أو حدود CPU/RAM.
2. اختبار ذلك قبل الكود، ثم تشغيل اختبارات البحث والترجمة والعزل والبناء.
3. توفير اختبار SSH مؤقت، مثبت بإصدار محدد، بلا نشر أو شراء أو استدعاء CJ. قياس HTTP للبحث العام على مراحل 1/5/10/20/40، وقياس النموذج بمدخلات متطابقة ومختلفة، مع فصل نتيجة الذكاء من الرفض/الاحتياط.
4. إيقاف الاختبار عند نقص الذاكرة، ارتفاع الحمل، بطء الصحة، أخطاء HTTP أو انتهاء المهلة العامة. عدم حذف ملفات أو نماذج أو تغيير إعدادات الخادم.
5. النتائج الحية شرط لتحديد السعة ووضع خطة بحث الزوار الدلالي. البحث العام الحالي لا يستدعي النموذج؛ لا يجوز نسب أداء بحث SQL إلى ذكاء مفعّل. مشاركة الطلبات تخدم عشرات العبارات المتطابقة ولا تزعم خدمة عشرات العبارات الجديدة المختلفة.
6. بعد تقرير الخادم: استكمال دمج فهم قصد الزوار مع مسار استرجاع سريع، واختبار الجودة العربية والفلاتر والصلاحيات على بيانات فعلية؛ النشر اليدوي بعد التحقق فقط.
