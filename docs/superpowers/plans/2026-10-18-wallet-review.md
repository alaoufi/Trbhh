# Wallet review and recurrence prevention — approved 2026-10-18

Risk P0. User approved publishing receipt protection, one review queue, documented decisions, no invented historical invoices, no automatic approvals or balance/payment/store changes.

1. Add an append-only wallet review service using existing finance_audit. No schema migrations, balance edits, debit/refund executions, or backdated invoices. Read permission requires tax:view and wallets:view; decision additionally tax:approve. Bind every decision to a source fingerprint and expected prior decision. Lock a shared existing wallet row and target source within transaction before checking idempotency/evidence uniqueness. Replay returns prior result; conflicting replay/source drift must fail. Missing evidence remains open.
2. A complete decision must have an explicit classification, net amount bounded by saved amount, source reference, documentary reference and unique document-line identity. An operational ad link or wallet funding receipt alone is not documentary tax approval. No automatic classification. Support refund review only when linked to a verified original supply; enforce cumulative limits and the same classification. Reject duplicate documentary lines and invoice overlap, fail closed on source/audit truncation or invalid evidence.
3. Read queue with source IDs, amount, reason, source reference, missing evidence and prior decisions. Accountant writes review notes explicitly through server action; no decisions executed by the agent. Server validates everything anew. Use existing tax section and authorization boundaries.
4. Tax monitor accepts only explicitly approved source-bound wallet decisions as canonical wallet supply/credit events; pending, missing-document and stale decisions stay in gaps. Preserve existing invoice derivation and deduplication. Never remove a gap without accounting for the reviewed event or explicit approved exclusion.
5. Prevent recurrence by preserving a structured stable service/source reference on new eligible wallet debits/refunds, without altering amounts or causing repeat charges. Audit existing service writers before changing them; add only compatible references and regression tests.
6. TDD, authorization/concurrency/idempotency tests, queue rendering tests, related/full relevant tests, typecheck, eslint and build. Independent security/spec review before commits/push. No production publish/financial actions in agent work; provide one pinned deployment command including receipt privacy checks and clear cached-response failure.

Work ownership: backend service+pure model agent; source-reference prevention agent; UI/server action agent; root integrates tax-monitor adapter, reviews, tests and release artifact. Shared files require coordination before edits.
