# شجرة الأقسام والإعلانات — 2026-10-23

P2. المستخدم طلب عرضاً متداخلاً قابلاً للتمدد: عدد الفروع وإعلانات الرئيسي، عدد إعلانات الفرع، عمر كل إعلان، حذف الإعلان، حذف الفرع بعد إفراغه والرئيسي بعد فروعه، وتلوين المكرر.

## التنفيذ
- مهمة tree ضمن /admin/categories. المصدر cfg الحالي دون إعادة بناء الأقسام، ومعه تجميع ads لكل category_id/subcategory_id مرة واحدة يشمل جميع الحالات.
- عدد الرئيسي اتحاد إعلاناته المباشرة وإعلانات فروعه دون عد مزدوج داخله. السجلات غير المتوافقة بين الرئيسي والفرعي قابلة للوصول، ولا تتجاهلها شروط الحذف.
- details للرئيسي والفرع وقائمة إعلاناته. القوائم محملة عند فتحها فقط، 25 إعلاناً مع cursor؛ لا تحميل لكل إعلانات السيرفر على الدخول.
- العمر من created_at بوقت نسبي، وتاريخ كامل عند المؤشر، وبيان واضح للتاريخ غير المتاح.
- الألوان تطبيع أسماء عربية مع أسر تداخل معروفة للمراجعة. لا تعني تطابقاً مضموناً أو إذن حذف تلقائي. كل معرف يبقى مستقلاً.

## الحذف والصلاحيات
- العمليات requireAccess مستقلة على الخادم. قراءة الإعلان ads:view، الأرشفة ads:archive، الحذف النهائي ads:delete، حذف العقد categories:delete.
- سياسة الموقع محفوظة: archive ثم delete بطلب وقصد وتأكيد منفصل. إعادة طلب archive لا تتحول إلى delete بعد تغير الحالة.
- معاملات Serializable وأقفال FOR UPDATE. إعادة فحص الأطفال والإعلانات بكل الحالات والمراجع المسماة والـFK المعلنة. القسم غير الفارغ يرفض؛ المراجع الأخرى غير المعروفة تمنع الحذف، بما فيها CJ والمالية والمحادثات والتفضيلات.
- حذف الإعلان النهائي يزيل بياناته المحلية المعروفة فقط (الصور والحقول والمشاهدات والمفضلة والتواصل والتذكيرات)، ولا يحذف ملفات الوسائط نفسها أو السجلات المالية/التجارية/المحادثات. وجود تلك السجلات يمنع الحذف.
- التحقق من InnoDB وتوفر الجداول قبل التنظيف؛ فشل الفحص يمنع العملية. تعريف الفرع يحفظ في سجل audit قبل إزالته؛ كل الحذف والأرشفة يسجل مع actor في المعاملة نفسها. قيم تصنيف يتيمة غير محسومة تمنع حذف الفرع، ولا تنظف عشوائياً.
- لا مخطط جديد، لا تعديل على الأسعار/المدفوعات/أعلام المتجر أو شراء CJ، ولا حذف/دمج أثناء النشر.

## التحقق
- الاختبارات الجديدة تغطي العد المتداخل والتصنيف غير المتوافق، الألوان، الحذف المشروط، القفل والمعاملة، المراجع المالية، فقد جرد المراجع، محركات غير معاملية، idempotent archive، القصد المزور، صلاحيات العرض/الأرشفة/الحذف، والصفحات المحدودة.
- مراجعة مستقلة من requesting-code-review: أصلحت فصل ads:archive عن ads:delete مع اختبار رفض. لم تبق ملاحظات مهمة بعد إعادة المراجعة.
- Edge فعلي عند 1440 و390، مع محاكاة الاستدعاءات فقط: lazy load، توحيد اللون، العمر، تعطيل حذف غير الفارغ، إلغاء التأكيد، أرشفة ثم حذف، تحديث العدد وعدم تجاوز العرض. ليست عمليات على قاعدة إنتاج.
- TypeScript والبناء ناجحان؛ ESLint صفر أخطاء و7 تحذيرات سابقة. المجموعة العامة النهائية 3662 ناجحاً و9 متجاوزة في 452 ملفاً. أول تشغيل واجه مهلتي Prisma CLI؛ إعادة نهائية منفردة بعد البناء نجحت دون تغيير التأكيدات أو المهل.
- لم يتم اختبار الحذف على قاعدة إنتاج أو قاعدة MySQL فعلية؛ سلامة المعاملات تستند إلى التحقق البرمجي واختبارات مزود معاملات محاكى. الإنتاج عند تجهيز النشر 4cd10eb4.
