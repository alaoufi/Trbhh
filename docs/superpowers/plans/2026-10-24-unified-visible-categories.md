# توحيد الأقسام الظاهرة بين الإدارة والإضافة

المقارنة الحية بالمعرفات: 23 رئيسياً ظاهراً في الإدارة مقابل9 في الإضافة؛14 مستبعداً. مثال47 الأطفال والألعاب:3فروع ظاهرة بلا تعريفات حقول نسخة0. الإصلاح السابق عالج رئيسياً بلا فروع ولم يعالج الفروع بلا تعريف.

المطلوب: حالة الظهور هي معيار قوائم الإضافة. تعاريف الحقول لا تحدد ظهور الأقسام. إبقاء البحث العام المقيد بالإعلانات منفصلاً حسب طلب المستخدم السابق.

الحل: اختيار رئيسي وفرعي من جميع النشطة وفق مصدر موحد؛ الفروع بلا تعريف متاحة لبيانات الإعلان الأساسية وتتحقق نسختها0 على الخادم داخل المعاملة، دون إنشاء تعريف وهمي أو قبول قيم مخصصة أو سعر غير معرف. التعريف التالف لا يخفي الرئيسي: يظهر الفرع مع سبب التعطيل ويظل الحفظ ممنوعاً حتى إصلاحه. التعاريف الصحيحة وحقولها وإلزامها لا تتغير.

التحقق: مقارنة23معرفاً/اسماً/ترتيباً بين إعداد الإدارة والإضافة، فروع بلا تعريف ومخفية وتالفة وصحيحة، منع تجاوز تعريف موجود بوسم0/قيم مزورة، واختبارات إضافة/تعديل وتصنيف الأب الخالي، متصفح1440/390، البناء والأنواع ومجموعة المشروع. لا تغيير بيانات الموقع ولا نشر إعلان/دفع خلال الفحص. نشر يدوي بكود مثبت الإصدار للمستخدم.

مراجعة مستقلة: تم التقاط خطر تصفير القيم التجارية للإعلان القديم ثم إصلاحه. helper الحفظ الأساسي يحفظ القيم الخمس من صف الإعلان المقفول إذا لم يتغير الرئيسي والفرعي، وتبقى في آخر بيانات التعديل. اختبار تراجع فشل قبل الإصلاح ونجح بعده. تجربة النموذج محلياً تطابق23معرفاً وترتيبها وتختار كل فرع بلا تعريف على1440و390؛ لا نشر حقيقي أو اتصال قاعدة إنتاج.
