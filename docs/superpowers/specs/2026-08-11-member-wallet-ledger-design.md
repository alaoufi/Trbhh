# محفظة الأعضاء والسجل المالي — تصميم

## الهدف

تطوير محفظة تربح إلى سجل مالي قابل للتدقيق، يوضح للعضو والإدارة كل شحن أو خصم أو استرداد وخدمة مدفوعة، مع دورة موافقة وتنفيذ عادلة للخدمات الخاصة التي ينشئها المدير.

## الحدود

- الرصيد هو وسيلة الدفع الوحيدة داخل الموقع. لا توجد مدفوعات مباشرة للخدمات.
- الشحن يأتي من تحويل بنكي أو بوابة دفع إلكترونية عند تفعيلها لاحقًا.
- لا تُفعل أي بوابة دفع ولا تحفظ مفاتيحها ضمن هذا العمل؛ يقتصر العمل على واجهة تكامل وحالات مرجعية آمنة.
- لا يغيّر هذا العمل موقع عقار تربح أو فرع `staging`.

## نموذج السجل المالي

يبقى `wallet_txns` مصدر الحقيقة لتغير الرصيد، وتبقى `wallet_topups` مصدر تفاصيل الشحن. يضاف كيان مستقل لأوامر الخدمات الخاصة لربط دورة الموافقة والتنفيذ والاسترداد بحركات المحفظة.

كل حركة مالية تحمل رقمًا قابلاً للبحث، العضو، المبلغ بإشارة موجبة أو سالبة، السبب، الوصف، وقت الإنشاء، ورابطًا اختياريًا إلى الخدمة أو الإعلان المعني. يمنع الخصم المتكرر عبر مرجع عملية فريد لكل أمر خدمة.

## أمر الخدمة الخاصة

ينشئه المدير لعضو محدد بالحقول التالية:

- اسم الخدمة ووصفها.
- القيمة بالريال.
- بداية الخدمة ونهايتها.
- مهلة قبول العضو.
- حالة: `بانتظار القبول`، `ملغى قبل القبول`، `بانتظار التنفيذ`، `نشط`، `مكتمل`، `ملغى بعد البدء`.

التدفق:

1. ينشئ المدير الأمر بدون أي خصم ويظهر للعضو ضمن الخدمات المعلقة.
2. تعرض الصفحة للعضو رصيده المتاح والقيمة المطلوبة. لا يظهر زر القبول فعالًا إن كان الرصيد أقل من المبلغ.
3. عند قبول العضو، تنفذ معاملة ذرية: التحقق من الرصيد ثم الخصم مرة واحدة ثم نقل الأمر إلى `بانتظار التنفيذ`.
4. عند تأكيد العضو «تم التنفيذ»، يبدأ الأمر ويصبح `نشطًا` من وقت التأكيد أو من وقت البداية المحدد، أيهما أحدث.
5. قبل القبول يستطيع المدير الإلغاء، ويلغي النظام تلقائيًا بعد المهلة؛ لا يوجد خصم في الحالتين.
6. أثناء التنفيذ يستطيع العضو إلغاء الخدمة. يحسب الاسترداد بنسبة الأيام غير المستخدمة: `المبلغ × الأيام المتبقية ÷ إجمالي الأيام`، ويقرب إلى هللتين. تسجل حركة استرداد موجبة ويصبح الأمر `ملغى بعد البدء`.
7. لا يعاد الرصيد للخدمة المكتملة أو المنتهية بالكامل. يحتفظ المدير بسجل سبب الإلغاء أو الاسترداد.

## تجربة العضو

في الحساب يظهر رابط «محفظتي» مباشرة أسفل «الرئيسية» وبشكل أوضح عند تسجيل الدخول. تعرض الصفحة بطاقة رصيد أخضر، كبير وغامق، ثم ثلاثة تبويبات:

1. **شحن الرصيد:** طلبات الشحن، المبلغ، الطريقة (تحويل بنكي أو بطاقة/بوابة)، المرجع، الإيصال، والحالة.
2. **الخدمات النشطة:** أوامر الخدمات الخاصة والمدفوعة القائمة مع البداية والنهاية والمهلة وحالة التنفيذ وزر القبول أو التأكيد أو الإلغاء عند السماح.
3. **سجل العمليات:** كل الخصومات والاستردادات والشحنات بترتيب زمني مع التفاصيل.

يبحث العضو داخل محفظته بالوصف، اسم الخدمة، رقم العملية، مرجع الدفع، ورقم الإعلان. الفلاتر: النوع، الحالة، الفترة، وقيمة المبلغ. لا يمكنه الوصول إلا إلى حركاته.

## تجربة الإدارة

يضاف تبويب «محفظة الأعضاء» تحت المال والمشتريات. يعرض فقط الأعضاء ذوي التعاملات المالية، مع الاسم، الرصيد المتاح، إجمالي الشحن، إجمالي الخصم، المبلغ المعلق، وعدد الخدمات النشطة.

يدعم البحث الذكي بالاسم، الجوال، البريد، رقم العضو، رقم العملية، مرجع الدفع، اسم الخدمة، أو رقم الإعلان. وتشمل الفلاتر نوع الحركة، طريقة الشحن، الحالة، التاريخ، ونطاق القيمة.

فتح العضو يعرض محفظته الكاملة بنفس التسلسل المالي مع تفاصيل الشحن والخدمات. في صفحات موافقة الخدمات المدفوعة تظهر قيمة الخصم والرصيد المتاح وكفاية الرصيد قبل أي اعتماد. لا يخصم الأمر إلا عند قبول العضو، ولا يستطيع المدير تجاوز تحقق الرصيد.

## الأمان والاتساق

- كل دوال العرض والتعديل تفرض صلاحية العضو أو صلاحية الإدارة القائمة.
- خصم قبول الخدمة والاسترداد ينفذان داخل معاملة قاعدة بيانات مع قفل/شرط رصيد يمنع الرصيد السالب والخصم المزدوج.
- لا يقبل webhook للشحن لاحقًا إلا بعد التحقق من توقيع المزود ومطابقة المرجع؛ لا تعتبر إعادة التوجيه من المتصفح إثبات دفع.
- لا تظهر بيانات إيصال أو مراجع حساسة إلا لصاحب العملية والإدارة المخولة.
- تسجل الأحداث الإدارية المهمة: إنشاء الخدمة، الإلغاء اليدوي، بدء التنفيذ، تأكيد العضو، والاسترداد.

## الاختبار والقبول

- اختبارات وحدة لحساب الاسترداد، التحقق من الرصيد، منع الخصم المكرر، انتهاء مهلة الموافقة، وفلاتر البحث.
- اختبار تكامل لدورة: إنشاء أمر → قبول مع رصيد كافٍ → خصم → تأكيد التنفيذ → إلغاء جزئي → استرداد نسبي.
- اختبار رفض القبول عند نقص الرصيد، والإلغاء الآلي قبل القبول بلا حركة خصم.
- فحص صلاحيات العضو مقابل الإدارة، وبناء TypeScript والاختبارات قبل النشر.
- قبل النشر: نسخة احتياطية كاملة، نشر تربح فقط، ثم فحص مسارات المحفظة وواجهات الإدارة والصحة العامة.
