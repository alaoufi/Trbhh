# تربح — تصميم التطوير الشامل ونظام الأقسام

## الهدف

تطوير تربح على مراحل مرتبة لتحسين السرعة، الأمان، الخدمات، وسهولة الاستخدام، ثم إعادة بناء الأقسام بطريقة متخصصة تخدم اختلاف الحقول، مع ترحيل الإعلانات الحالية بأمان ومن دون نشر قبل اكتمال التجربة والتحقق.

## حدود التنفيذ

- العمل يبدأ في بيئة تجريبية منفصلة.
- لا تعديل مباشر على إنتاج أو تفعيل عام قبل نسخة احتياطية، اختبار، وموافقة نهائية.
- البيانات الحالية لا تُحذف.
- إخفاء القسم يمنع الإعلانات الجديدة منه، لكنه لا يخفي الإعلانات المنشورة سابقاً.
- كل إعلان يملك قسماً رئيسياً واحداً وفرعاً واحداً اختيارياً.

## خارطة المراحل

### المرحلة 1: الأمان والاستقرار

- تثبيت تحديثات Next.js وSharp المصححة.
- إزالة الأسرار الافتراضية من Docker Compose.
- تضييق مصادر الصور والوسائط الخارجية.
- مراجعة المصادقة، الصلاحيات، الرفع، الدفع، والنسخ الاحتياطي.
- تشغيل typecheck وlint وtest وbuild وaudit.

### المرحلة 2: السرعة

- قياس TTFB وLCP وCLS وطلبات الصور على الهاتف وسطح المكتب.
- تحسين استعلامات الصفحة الرئيسية والبحث والفهرسة.
- استخدام التخزين المؤقت للزوار غير المسجلين فقط.
- تحسين الصور وأحجامها والتحميل الكسول.
- إعادة القياس قبل وبعد كل تغيير.

### المرحلة 3: الخدمات

- تحسين نشر الإعلان والترويج والباقات والمحفظة.
- توضيح الخدمات المدفوعة والرصيد قبل بدء العملية.
- تحسين المتاجر والمنتجات والرسائل والمزادات والتقارير.
- الحفاظ على الصلاحيات وسجل التدقيق لكل إجراء إداري.

### المرحلة 4: سهولة الاستخدام

- مراجعة الهاتف أولاً ومسارات التسجيل والدخول.
- تبسيط إنشاء الإعلان إلى خطوات واضحة.
- تحسين البحث والفلترة والموقع الجغرافي.
- توحيد الرسائل وحالات الخطأ والتحميل.
- اختبار الوصول واللغة العربية RTL.

### المرحلة 5: نظام الأقسام المتخصص

الأقسام الأولية:

1. عقارات
2. سيارات ومستلزماتها
3. نقليات ومعدات ثقيلة
4. زراعة ومشاتل وأعلاف
5. مواشي ومستلزماتها
6. أواني منزلية
7. ديكورات منزلية
8. مواد بناء ومقاولات
9. وظائف
10. خدمات
11. فرص تجارية
12. منتجات
13. أخرى

الأقسام المتداخلة تُوزع على فروع، مثل سيارات، قطع غيار، إكسسوارات، خدمات سيارات داخل «سيارات ومستلزماتها»، وشاحنات، رافعات، معدات إنشائية، نقل وخدمات لوجستية داخل «نقليات ومعدات ثقيلة».

## تصميم قاعدة البيانات

سيُعاد استخدام `categories` و`sub_categories` وحقول الإعلانات الحالية بعد مراجعتها. ستُضاف طبقات مستقلة عند الحاجة:

- تعريفات حقول القسم: الاسم، المفتاح، النوع، الترتيب، الإلزامية، الحالة.
- قيم حقول الإعلان مع نوع قيمة مضبوط.
- سجل اقتراحات التصنيف والثقة والمطابقة والمراجع.
- دفعات الترحيل مع عدد النجاح والفشل والرجوع.
- سجل تدقيق للإجراءات الجماعية.

سيُحدّث `prisma/schema.prisma` و`src/data/schema-sync.ts` معاً، مع الحفاظ على التوافق مع الجداول القديمة وعدم حذف أي عمود حالي.

## الترحيل والتصنيف

- تحليل العنوان والوصف والبيانات الحالية.
- ثقة عالية: اعتماد تلقائي.
- ثقة متوسطة: إدراج في جدول مراجعة جماعي.
- ثقة منخفضة أو بلا تطابق: إسناد إلى «أخرى».
- دعم التحديد الجماعي، التحويل، وتسجيل المنفذ والوقت والسبب.
- دعم التراجع عن الدفعة قبل اعتمادها نهائياً.
- الإعلانات الحالية تبقى منشورة حتى عند إخفاء قسمها.

## لوحة الإدارة

- إدارة الأقسام والفروع والتفعيل والترتيب.
- بناء حقول كل قسم والتحكم في ظهورها وإلزاميتها.
- شاشة التصنيف المقترح مع فلترة حسب الثقة.
- تحويل جماعي مع معاينة قبل التطبيق.
- تقرير أخطاء وسجل تدقيق ونقطة تراجع.

## الاختبارات وبوابة النشر

قبل كل نشر:

- نسخة احتياطية للكود وقاعدة البيانات والوسائط عند الحاجة.
- تجربة على قاعدة منفصلة وبيانات صناعية.
- اختبارات TypeScript وESLint وVitest وProduction Build.
- اختبار يدوي لمسارات التسجيل، نشر الإعلان، التعديل، البحث، التصفية، المتجر، الترويج، واللوحة.
- اختبار ترحيل قابل للتكرار والتراجع.
- فحص الموقع التجريبي كزائر وعضو ومدير.
- لا نشر إنتاج أو تفعيل الأقسام قبل نجاح جميع البوابات.
