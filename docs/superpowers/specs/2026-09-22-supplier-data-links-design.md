# روابط بيانات المورد وتفويض سلة

## الهدف

استبدال ملف Excel كمسار التسجيل الأساسي برابط آمن وفريد لكل مورد. يعبئ صاحب المتجر بياناته ويحفظها كمسودة ثم يرسلها، وتراجع الإدارة البيانات وتعتمدها قبل إتاحة رابط المتجر ورابط تفويض سلة. يبقى Excel خيارًا احتياطيًا داخل الإدارة.

## التدفق المعتمد

1. تنشئ الإدارة موردًا باسم مبدئي من لوحة الموردين.
2. تنشئ الإدارة رابط بيانات للمورد، صالحًا سبعة أيام، وتنسخه أو تفتحه.
3. يفتح صاحب المتجر نموذجًا عربيًا عامًا لا يتطلب تسجيل الدخول ولا يعرض أي لوحة أو بيانات إدارية.
4. يحفظ صاحب المتجر مسودة أو يرسل البيانات للمراجعة.
5. تظهر حالة الطلب والبيانات المرسلة داخل بطاقة المورد للإدارة فقط.
6. تعتمد الإدارة البيانات بعد التحقق. الاعتماد وحده يحدث ملف المورد وبيانات الانضمام المشفرة.
7. بعد الاعتماد تظهر للإدارة أزرار فتح ونسخ رابط المتجر، ويظهر مولد رابط تفويض سلة إن لم يكن المتجر متصلًا.

## الأمان

- يتكون الرابط من رمز عشوائي بقوة 256 بت، ولا تحفظ قاعدة البيانات إلا بصمته SHA-256.
- لكل مورد دعوة بيانات فعالة واحدة. إعادة الإصدار تلغي الرابط السابق فورًا وتزيد رقم الجيل.
- يمكن للإدارة إلغاء الرابط في أي وقت، وتنتهي صلاحيته تلقائيًا بعد سبعة أيام.
- الرابط لا ينشئ جلسة مستخدم أو مشرف ولا يستدعي أي صلاحية إدارية.
- صفحة المورد لا تعرض بيانات المورد الحالية. تعرض فقط المسودة التي أدخلها صاحب الرابط نفسه.
- تحفظ المسودة مشفرة بمفتاح `SUPPLIER_TOKEN_ENCRYPTION_KEY` مع سياق تشفير خاص بالمورد وجيل الدعوة.
- تمنع طلبات الحفظ عبر المواقع الأخرى بفحص `Origin`، وتحدد أحجام الحقول باستخدام تعريفات التسجيل الحالية.
- الاعتماد يتطلب صلاحية `suppliers:edit` ويعيد استخدام فحوص التعارض الحالية للسجل التجاري ورابط المتجر.
- لا يغير هذا التدفق OAuth أو Callback أو Webhook، ولا يفعّل الشراء أو النشر التلقائي.

## حالات الدعوة

- `open`: الرابط صدر ولم تحفظ بيانات.
- `draft`: حفظ صاحب المتجر مسودة قابلة للتعديل.
- `submitted`: أرسل البيانات وأصبحت بانتظار الإدارة؛ لا يقبل الرابط تعديلات جديدة.
- `approved`: اعتمدت الإدارة البيانات؛ يغلق رابط البيانات.
- `revoked`: ألغت الإدارة الرابط.

## واجهة الإدارة

تظهر في كل بطاقة مورد لوحة «رابط بيانات المورد» فيها إنشاء، نسخ، فتح، إلغاء، وإعادة إصدار. عند وصول الطلب تعرض الإدارة الحقول في مجموعات مع إخفاء الهوية والآيبان جزئيًا، ثم تعتمد أو ترفض لإعادة فتح الطلب للتعديل. بعد الاعتماد يظهر رابط المتجر مع فتح ونسخ، ويعاد استخدام مكوّن تفويض سلة الحالي لإنشاء رابط التفويض وفتحه ونسخه.

## واجهة المورد

النموذج متجاوب ومقسم إلى: المنشأة، المسؤول، التشغيل والشحن، السياسات، والبيانات البنكية والموافقات. يوضح أن الحفظ كمسودة لا يرسل الطلب، وأن الإرسال النهائي يمنع التعديل حتى تعيده الإدارة. لا يحتوي أي تنقل للإدارة أو بيانات داخلية.

## البيانات والترحيل

يضاف جدول `supplier_data_invitations` مرتبط بالمورد مع منع الحذف، ويحتوي بصمة الرمز، الجيل، الحالة، المسودة المشفرة، تاريخ الانتهاء والإرسال والاعتماد، ومعرفي مشرف الإصدار والاعتماد. تضاف البنية إلى DDL المتحقق منه وإلى Prisma للتوثيق، مع إبقاء `supplier_onboarding` مصدر البيانات المعتمدة.

## التحقق

تشمل الاختبارات: توليد الرمز وبصمته، الإلغاء وإعادة الإصدار، الانتهاء، عزل الموردين، حفظ المسودة والإرسال، منع Origin الخارجي، عدم وجود أي صلاحية إدارية في الصفحة العامة، مراجعة الإدارة، منع الاعتماد دون إرسال، فحوص التعارض الحالية، ظهور روابط المتجر وسلة بعد الاعتماد، وبقاء Excel كخيار احتياطي. تجرى اختبارات الوحدة والتكامل وTypeScript وESLint والبناء قبل عرض النتيجة، دون نشر للإنتاج.
