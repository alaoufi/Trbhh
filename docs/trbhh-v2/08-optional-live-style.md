# المظهر الاختياري داخل التطبيق الأساسي

## الفرق عن المعاينة المنشورة

معاينة Sites المنشورة تطبيق ثابت يحتوي لقطة للإعلانات العامة. ليست اتصالاً حياً، ولا تصبح اتصالاً حياً بإضافة متغير قاعدة البيانات إلى إعداداتها.

التكامل الجديد داخل `src/` يستخدم صفحات التطبيق الأساسي ومصادر بياناته وإعداداته الحالية. اختيار `design=v2` يغيّر العرض فقط، دون قاعدة بيانات جديدة أو استيراد الإعلانات أو تكرار حساب العضو. لا تُنقل إعدادات الخادم كاملة إلى المتصفح؛ يتلقى فقط إتاحة المظهر واسمه ووصفه.

## التحكم والرجوع

- الإتاحة من `v2_design_on` في إعدادات الإدارة؛ الافتراضي معطّل.
- `v2_design_label` و`v2_design_description` نصوص العرض القابلة للتعديل.
- القالب الحالي يبقى الافتراضي، ويمكن اختيار القالب الجديد من القائمة دون تغيير حساب المستخدم.
- حفظ الاختيار في متصفح الزائر فقط. إيقاف الإتاحة يُبطل اختيار V2 القديم عند إعادة التحميل.
- المتاجر المستقلة والإدارة والدفع ليست هدفاً لإعادة التصميم.
- لا تغيير لمخطط القاعدة، بيانات الإعلانات، صورها، إعدادات بوابة الدفع أو إجراءات الدفع.

## بوابة التجربة الحية

هذه الوثيقة لا تعني نشر المظهر أو تفعيله. التطبيق الأساسي ينفذ مزامنة المخطط ونشر الإعلانات المجدولة وعمليات دورة الحياة؛ لذلك لا يجوز تشغيل نسخة تجريبية كاملة ببيانات اتصال الإنتاج القابلة للكتابة.

قبل معاينة حية مستقلة يلزم تشغيل خادم تجريبي معزول، واتصال محدود الصلاحيات، وضبط الجلسات والكاش والمهام والتخزين والإشعارات والمدفوعات بحيث لا تُحدث التجربة آثاراً على الموقع الحي. بيانات الدفع والرسائل والمعلومات الخاصة لا تُصدّر إلى موقع ثابت أو مستودع عام.

قبل التفعيل النهائي: نسخة احتياطية ونقطة رجوع، فحوصات الأنواع والاختبارات والبناء، ثم اختبار مرئي للعرضين والإعلانات والصور والإعدادات الفعلية والدخول والدفع في بيئة مناسبة. لا يُعتمد نجاح البناء وحده دليلاً على نجاح الاتصال بالقاعدة الحية.

## نتائج التنفيذ والاختبار المحلي — 19 سبتمبر 2026

- أُدمجت تحديثات الإنتاج الحالية في فرع التجربة قبل العمل للحفاظ على تصحيح صور HEIC وإعدادات الدفع من البطاقة.
- نجح البناء الكامل باستخدام قاعدة MySQL مؤقتة على الجهاز، محصورة بعنوان loopback، دون استخدام أسرار الإنتاج أو بياناته.
- نجح TypeScript و296 اختبار وحدة، ونجح lint دون أخطاء مع خمسة تحذيرات سابقة. استُخدم إصدار pnpm المثبّت في المشروع (9.15.9) لبوابات lint/test/build. بقيت تحذيرات البناء السابقة الخاصة بـ middleware وتتبع ملفات التخزين، وليست أخطاء بناء.
- نجحت عشرة اختبارات مرئية للمكوّنات على 390 و1440 بكسل، فاتح وليلي، مع التحقق من تباين النصوص، الأعمدة وعدم تجاوز العرض، وحماية نطاق الإدارة والدفع والمتجر.
- نجح اختبار التطبيق الحقيقي مع قاعدة اختبار نشطة: الافتراضي يبقى كلاسيكياً، اختيار V2 للزائر، استمراره بعد إعادة التحميل والتنقل للبحث، نفس معرّفات الإعلانات، عدم تجاوز شاشة الجوال، دخول حساب اختبار، تزامن قائمة التصميم وصفحة القوالب، والرجوع إلى الافتراضي بعد تعطيل الإتاحة وانتهاء الكاش.
- لا يتضمن هذا اختبار معاملة دفع أو قبولاً لاتصال قاعدة الإنتاج. لم يتغير رابط Sites الثابت بهذه التعديلات.

### تصحيح اكتشفه الاختبار

كشف الاختبار الحقيقي خللاً سابقاً في `search-card-visibility.ts`: عند كون الباقة الافتراضية غير محدودة وعدم وجود اشتراكات معيّنة، كان شرط فارغ داخل `OR` لا يعني السماح بكل الإعلانات لدى Prisma. النتيجة: إعلانات تظهر في الرئيسية وتختفي من البحث. أصبح هذا الفرع يعيد شرط استبعاد المحظورين فقط دون تقييد زمني؛ بقيت قيود الباقات المحدودة والاشتراكات الأخرى كما هي. أضيفت اختبارات رجوع وأُعيد اختبار البحث على MySQL فعلي.

### إعادة الاختبارات

```powershell
npx --yes pnpm@9.15.9 lint
npx --yes pnpm@9.15.9 test
npx tsc --noEmit
# DATABASE_URL هنا لقاعدة اختبار معزولة فقط، وليست الإنتاج.
npx --yes pnpm@9.15.9 build
node node_modules/vitest/vitest.mjs run --config tests/site-design-browser.config.ts
node tests/browser/site-design-runtime.mjs
```

اختبار المكوّنات يستخدم Edge بدون واجهة. يمكن تحديد `PLAYWRIGHT_MODULE` لمسار Playwright متوافق مع المتصفح المثبت. اختبار التطبيق يرفض أي قاعدة غير `trbhh_style_test` على `127.0.0.1:33309`، ويتطلب جدولَي إعلانات وأعضاء فارغين ومنفذ 4189 غير مستخدم؛ ينشئ بيانات اختبار محلية مؤقتة، يعيد الإعدادات ويحذف سجلاته ويوقف عملية التطبيق عند الانتهاء. يلزم إنشاء المخطط أولاً بـ Prisma. بيانات الاختبار ليست إعلانات حية ولا تُنشر كمعاينة للمستخدم.
