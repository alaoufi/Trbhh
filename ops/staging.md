# بيئة التجريب (Staging) — رابط سرّي غير معلن لتجربة الميزات قبل الإطلاق

الهدف: تجربة أي ميزة على **رابط منفصل محمي بكلمة مرور** (`https://beta.trbhh.com`)،
بحاويات وقاعدة بيانات **معزولة تماماً** عن الموقع الحيّ — فلا يتأثّر الإنتاج ولا بيانات
الأعضاء، ولا يراه أحد من العامة.

النموذج: **الإنتاج** يُنشر من فرع `claude/hostinger-vps-project-amw8vb` → `trbhh.com`.
**التجريب** يُنشر من فرع `staging` → `beta.trbhh.com` (دليل ومشروع Docker وقاعدة MySQL
مستقلّة على نفس الخادم — عبر profile «localdb»، لا تلمس قاعدة الإنتاج).

## العزل التام
- أسماء حاويات مختلفة: `trbhh-staging-app` / `trbhh-staging-db` / `trbhh-staging-redis`.
- منفذ 3081 (الإنتاج على 3080)، حجوم مسبوقة بـ `trbhh-staging_…`، وقاعدة MySQL خاصة.
- سرّ `AUTH_SECRET` مختلف، و`.env` منفصل — لا تداخل مع الإنتاج بأي شكل.

---

## التجهيز (مرّة واحدة)

### 1) تشغيل آلي ذاتي‑التجهيز (عبر خط النشر الآمن نفسه)
مسار **`deploy-staging.yml`** ذاتي‑التجهيز: عند أول دفع لفرع `staging` ينفّذ على الخادم
استنساخ المستودع في `/root/trbhh-staging`، توليد `.env` خاص (منفذ 3081 + قاعدة تجريب
مستقلّة + سرّ جديد)، وتشغيل الحاويات المعزولة. النتيجة: التطبيق التجريبي يعمل داخلياً على
`127.0.0.1:3081`. **لا يمسّ الإنتاج ولا قاعدته.** الدفعات التالية تحدّثه تلقائياً.

### 2) خطوتك في لوحة تحكّم الخادم + DNS (الوحيدة التي تحتاج وصولك)
هذه لا يستطيع المساعد تنفيذها (لا يملك وصولاً للوحة/النطاق) — بضع نقرات:
1. **DNS**: سجل `A` باسم `beta` → نفس IP خادمك (تلقائي إن كانت لوحتك تدير DNS).
2. **موقع/نطاق** `beta.trbhh.com` → **Reverse Proxy** إلى `http://127.0.0.1:3081`.
3. فعّل **SSL (Let's Encrypt)**.
4. فعّل **Basic Auth (كلمة مرور)** — فلا يفتحه إلا من يملك الكلمة (غير معلن).

> مسار `deploy-staging.yml` يطبع نوع لوحتك المكتشَف (CloudPanel/aaPanel/…) في سجلّ
> التشغيل ليعطيك المساعد خطوات النقر الدقيقة لها.

---

## الاستخدام اليومي (بعد التجهيز)
1. تُطوَّر الميزة وتُدفع إلى فرع `staging` → تُنشر تلقائياً على `beta.trbhh.com` (عبر
   `deploy-staging.yml`).
2. تجرّبها أنت على الرابط السرّي (كلمة مرور Basic Auth أولاً).
3. عند رضاك، تُدمج إلى فرع الإنتاج → تظهر على `trbhh.com` الحيّ.

## كيف تدخل الرابط المخفي؟
تفتح `https://beta.trbhh.com` (جوال أو كمبيوتر) → يظهر صندوق يطلب اسم مستخدم + كلمة
المرور (التي ضبطتها في الخطوة ٤) → تدخل الموقع كاملاً معزولاً. الزائر بلا كلمة المرور
يبقى عالقاً عند الصندوق. لوحة `/admin` تعمل داخل التجريب بحساب مدير **تجريبي** تُنشئه هناك.

## أسرار GitHub (اختيارية)
`STAGING_DIR` (افتراضي `/root/trbhh-staging`) · `PROD_DIR` (افتراضي `/root/trbhh`) —
تُضبط فقط إن اختلفت مساراتك. أسرار الخادم (VPS_HOST/USER/PORT/KEY) مشتركة مع الإنتاج.

## للتراجع (إزالة بيئة التجريب)
```bash
cd /root/trbhh-staging
docker compose --profile localdb -p trbhh-staging -f docker-compose.yml -f docker-compose.staging.yml down -v
cd /root && rm -rf /root/trbhh-staging
```
لا أثر على الإنتاج إطلاقاً.
